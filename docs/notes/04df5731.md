# Card 04df5731: diary links open blank unless the Diary tab was opened first

## Cause (confirmed by reading the code and by a test)
- `findDiarySession` (src/lib/diary/lookup.ts) only read `diary_sessions`. The only caller of
  `syncDiary` (which pulls sessions from Balla Bot and stores them) was the Diary page.
- `/journal/new?diary=<id>` and `/timer?diary=<id>` both call `findDiarySession`, so a session never
  synced came back null and the pages rendered as plain, un-filled pages.
- Not reproduced against the live mini (app cannot run on the laptop); reproduced as a unit test.

## Fix
- `findDiarySession` now: read; if missing, run `syncDiary` (same sync as the Diary tab), read again;
  null if still missing or the sync throws. Fixes both pages (shared helper).

## Decisions / ruled out
- Fix in the shared helper rather than each page, so both links and any future caller get it.
- No sync when the first read errors (database trouble) or the user isn't a diary user.
- Known limit: once the user has stored sessions, sync only looks 60 days back to 1 year ahead,
  so a link to a session older than that still opens a plain page (safe fallback).
- The two pages' own tests mock `findDiarySession`, so the new test lives in
  src/lib/diary/__tests__/lookup.test.ts.
